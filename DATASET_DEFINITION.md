# Dataset Definition

## 1. Project Objective

The project aims to develop and evaluate machine-learning models for
drug-likeness classification from molecular structure.

The primary molecular representation used by the pipeline is SMILES,
which is converted into standardized molecular representations before
feature generation.

---

## 2. Prediction Task

The initial modeling task will be formulated as binary classification.

Each molecular record will ultimately receive a target label:

- `1` — positive / drug-like class
- `0` — negative / non-drug-like or reference class

The exact operational definition of the positive and negative classes
must be established from the selected source datasets before model
training.

---

## 3. Label Provenance

Labels must originate from identifiable source datasets or explicitly
documented labeling rules.

The pipeline must retain the source of every label.

A label must never be assigned merely because a molecule "looks"
drug-like based on its molecular structure.

---

## 4. Molecular Identity

Molecular identity will initially be represented using canonical SMILES
generated by RDKit.

The original source representation will be retained separately.

Canonicalization is a representation step and does not by itself imply
that chemically distinct forms such as salts, tautomers, or stereoisomers
are equivalent.

---

## 5. Duplicate Handling

Duplicate records will be identified after molecular standardization.

Duplicate records will not be silently discarded.

The final dataset construction process will document:

- duplicate molecular identities
- number of records per molecular identity
- source provenance
- conflicting labels, if present

---

## 6. Conflicting Labels

If the same molecular identity receives different labels from source
records, the records must be retained during the audit stage.

Conflicting labels will not be resolved automatically.

A documented resolution policy will be established before creation of
the final modeling dataset.

---

## 7. Dataset Splitting

The project will evaluate molecular generalization rather than relying
solely on random record-level splitting.

The final splitting strategy will be explicitly documented before model
training.

Scaffold-based splitting will be considered as a primary evaluation
strategy because chemically similar molecules can otherwise appear
across training and evaluation sets.

---

## 8. Data Leakage

Information from validation or test records must not influence:

- preprocessing decisions learned from the training data
- feature selection
- hyperparameter optimization
- model selection
- threshold selection

Any transformation that learns parameters from data must be fitted only
on the appropriate training partition.

---

## 9. Final Dataset

The final modeling dataset should retain, where available:

- source identifier
- source dataset
- original SMILES
- canonical SMILES
- molecular validity
- standardization status
- target label
- label provenance

The dataset construction process must be reproducible from the source
data and documented preprocessing configuration.
