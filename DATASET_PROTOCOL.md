## Molecular Standardization Policy

### Current policy status

Draft — implementation baseline.

### SMILES parsing

Input molecular structures will be parsed using RDKit.

Invalid or unparsable SMILES will be rejected from the standardized molecular dataset and recorded separately during dataset construction.

### Canonical representation

Valid molecules will receive a canonical SMILES representation generated by RDKit.

Canonical SMILES will be used for deterministic molecular identity within the pipeline.

### Salts and mixtures

Salt and mixture handling will not be silently applied at this stage.

The project will explicitly define whether components are retained, removed, or standardized before the final dataset is constructed.

### Stereochemistry

Stereochemical information will be retained where it is represented in the input structure.

Stereochemistry will not be discarded merely to increase the number of duplicate matches.

### Tautomers

No tautomer normalization will be applied in the initial implementation.

A separate policy will be established if tautomer normalization becomes necessary for the final dataset.

### Duplicate molecules

Duplicate detection will be performed after standardization using the selected molecular identity representation.

Duplicate resolution will preserve provenance and will not silently discard records.

### Provenance

Original input structures will be preserved separately from standardized structures so that every transformation can be traced back to its source record.


## Molecular Record Structure

Each molecular record will retain the original input representation alongside standardized representations.

### Required fields

| Field | Description |
|---|---|
| `source_id` | Identifier assigned by the source dataset |
| `original_smiles` | Original SMILES exactly as received |
| `canonical_smiles` | Canonicalized SMILES generated by RDKit |
| `valid` | Whether the input SMILES can be parsed |
| `standardization_status` | Status describing the processing result |

### Provenance rule

The `original_smiles` field must not be overwritten during preprocessing.

All standardized representations are derived fields.

This allows preprocessing decisions to be audited and reproduced.
